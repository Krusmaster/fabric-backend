Three small steps

It lists the sources in a lakehouse, warehouse, SQL database or mirrored database, plans the connections, then creates the API for GraphQL item in your workspace, or just answers questions about the plan. Nothing is created until you ask for it, and asking again updates what is there instead of making a copy.

  1. 1

    Discover

    Point it at a workspace. It lists the sources and reads table and column names, nothing else.

    “Plan a backend over the shop lakehouse.”
  2. 2

    Understand

    Every key and connection comes with the rule that produced it, K0–K3 and R0–R3. Ambiguous columns are reported, never guessed.

    orders.customer_id → customers · R1
  3. 3

    Create

    One API for GraphQL item in your Fabric workspace, with nested relationships. Read-only queries from Claude after that.

    “Create it as shop_api.”

  • Your permissions, not ours

    You sign in with your own Microsoft work account; every call runs with what it can already see and do in Fabric.

  • Nothing stored

    Metadata and results pass through; tokens live in memory only, and there is no database of our own. Privacy.

  • Open source

    MIT licence. Read the inference rules, run it locally or host it yourself. GitHub.
