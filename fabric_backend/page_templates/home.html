What {{PRODUCT}} reads

Planning uses schema metadata. If you ask for data checks, samples or queries, the relevant counts or results pass through {{PRODUCT}} to Claude. Access depends on your Microsoft account and the permissions granted to the connector. Read how data and access are handled.

{{PRODUCT}} stores no table contents. Names, counts and the sample rows you ask for pass through the service in memory and reach your AI client; the hosted service runs in the EU, and you can run it in your own Azure to keep everything in your tenant. Where your data goes.

  • How it connects

    {{PRODUCT}} connects {{MCP_CLIENTS}} to Microsoft Fabric through MCP. You sign in with your Microsoft work account, and every call runs with your own Fabric permissions.

  • Nothing is created until you ask

    Planning and checking only read. Creating an API or views is a separate request, and the drafts create nothing.

  • Open source

    Read the code, inspect the inference rules or host {{PRODUCT}} yourself. The source is available under the MIT licence on GitHub.

Questions

Do you touch my data?

Planning reads schema metadata only: workspace, item, table and column names and types. The checks you ask for count in Fabric and return counts, not row values; sample_rows returns up to 20 rows of one table when you ask for them. Nothing passing through is kept after the request. On /check your files are read in your browser and are not uploaded. Privacy policy.

What does {{PRODUCT}} create in my Fabric, and when?

Nothing until you ask. Planning, checking and the drafts only read. The creating tools run as a dry run by default and show what they would create; only a call with dry_run=false creates the item. The one tool without a dry run, {{NO_DRY_RUN_TOOLS}}, creates or updates only the GraphQL API you name. No item is ever deleted and no table dropped.

What does my IT department need to approve?

One admin consent for the {{PRODUCT}} app in Microsoft Entra ID. Its permissions are delegated, so every call runs as the signed-in person with their own Fabric rights. The page for your IT department lists each permission and why, what is stored, and how to revoke it.

Can I try it without Fabric?

Yes. /check runs the same engine in your browser on CSV or Excel exports, or on a list of columns, with no account. The guided demo uses synthetic sample data.

How is this different from asking a chat assistant directly?

The proof. Every key and relationship comes with the named rule that produced it, or its source, such as the public source behind an SAP pack link, and the checks count against your rows: whether a key is unique, how many rows point at nothing, whether a total doubles in a join. The rules are in the open source code.
