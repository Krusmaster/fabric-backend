From tables to a GraphQL API

Each step is something you ask for in Claude. Nothing is created in Fabric until you ask for it.

  1. 1

    Choose your tables

    Start with a source in your Fabric workspace. {{PRODUCT}} reads its schema and proposes keys and relationships.

    “Plan a backend over the shop lakehouse.”
  2. 2

    Review the plan

    See the rule behind each suggestion. Ask Claude to check the plan against your data for duplicate keys, missing values and references with no matching row, then correct the relationships that need your judgement.

    “Check the plan against the data.”
  3. 3

    Create the API

    When you’re ready, ask Claude to create the GraphQL API in Fabric. If an API with that name already exists, {{PRODUCT}} updates it. You can then ask Claude to query it.

    “Create it as shop_api.”

Tested end to end on 26 October 2026, from Claude to a Fabric workspace with synthetic data: sign-in, plan, check, create and query. Test status per tool. Published in the official MCP Registry as com.krusgraph/krusgraph.

Explore a Fabric IQ ontology draft

{{PRODUCT}} can also turn the plan into a draft for a Fabric IQ ontology, with entity types, keys and relationships. Review the draft before importing it or creating an ontology item. Generating the draft does not deploy anything.

Entity types and keys

One entity type per table, with its key and properties. Tables without a key, or with a key of several columns, are flagged for review.

Relationship types

Each relationship in the plan becomes a relationship type, with the rule behind it.

Two ways in

Import the draft in the Fabric portal and follow its binding checklist, or create the ontology item from Claude once the operator has enabled that permission. Read about ontology drafts.

Ontology is a Microsoft Fabric preview feature. The draft format has been checked against recorded definitions; importing or creating an ontology from it has not been tested live yet.
