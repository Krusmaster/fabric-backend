What will {{PRODUCT}} access?

Only what the signed-in user can already reach. The hosted app asks for these delegated permissions, all approved by your admin once and all acting as the user:

PermissionUsed for
User.Read (Microsoft Graph)sign-in only
Workspace.Read.All, Item.Read.All (Fabric)listing sources and reading item metadata
GraphQLApi.ReadWrite.All (Fabric)creating or updating the one API for GraphQL item you ask for; never deleting
GraphQLApi.Execute.All (Fabric)running the read-only queries you ask for
user_impersonation (Azure SQL Database)reading table and column names from the SQL analytics endpoint

Why each one: Workspace.Read.All and Item.Read.All are what list_workspaces, list_sources, describe_backend, plan_drift and lineage read; GraphQLApi.ReadWrite.All is used by create_backend alone; GraphQLApi.Execute.All by query_graphql and app_readiness; the SQL permission by the tools that read table and column names or count rows (list_tables, plan_backend, validate_plan, sample_rows, the drafts). The tools that create semantic models, ontologies, data agents, notebooks and pipelines need Item.ReadWrite.All or a narrower permission per item type, which the hosted app does not ask for today. The docs mark them available when enabled by the operator: their dry runs work, and asked to create they answer consent with the permission’s name.

What passes through {{PRODUCT}}: planning uses schema metadata (workspace, item, table and column names and types). validate_plan and suggest_relationships check keys and references against the rows in Fabric and return counts. sample_rows returns up to 20 example rows of one table, and query_graphql returns the results you ask for. Metadata, requested samples and query results pass through {{PRODUCT}} to your client and are not kept after the request. Your tokens are exchanged on your behalf and held in memory only. The privacy policy explains this, the usage records and the technical logs.

Two steps stay manual in the Fabric portal because there is no API for them yet, and the connector tells you when they are needed: turning on introspection for the GraphQL item, and granting permissions on it to other apps.
