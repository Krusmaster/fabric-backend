Where your data goes

{{PRODUCT}} stores no table contents. Names, counts and the sample rows you ask for pass through the service in memory and reach your AI client; the hosted service runs in the EU, and you can run it in your own Azure, so that nothing passes through Kruse Consulting. Either way, your AI client and its AI provider receive the tools’ answers.

What the Entra app asks for, and why

An administrator approves the {{PRODUCT}} app once (admin consent). All its permissions are delegated: every call runs as the signed-in person, with that person’s own Fabric rights, so {{PRODUCT}} can reach nothing that person cannot already reach. The app asks for no application permissions. Every creating tool answers with what it would create until it is called with dry_run=false; it then creates or updates only the item named in the call.

What is stored, where and for how long

  • No table contents. Metadata (workspace, item, table and column names and types), the counts from checks, sample rows and query results pass through {{PRODUCT}} to the person’s MCP client and are not kept after the request.
  • Tokens. From Claude, tokens are exchanged on the person’s behalf (OAuth 2.0 on-behalf-of) and held in memory only, never written to disk or logs.{{#IF CLIENT_REGISTRATION}} From MCP clients other than Claude, which sign in through {{DOMAIN}}/oauth, the sign-in records are kept encrypted in {{REGISTRATION_WHERE}}; the privacy policy has the details.{{/IF}} The table below gives each token and how long it lives.
  • A usage record per tool call: the tool’s name, the outcome, the duration and, for creating tools, whether it was a dry run{{#IF USAGE_ORG}}, plus a salted hash of the organisation’s tenant id{{/IF}}. No user id, no table or column names.
  • Where: the service runs in Azure, Sweden Central (EU).{{#IF LOGS_KEPT_DAYS}} The usage records and the technical console log (no IP addresses, headers, tokens or query text) go to a Log Analytics workspace in the same region and are deleted after {{LOGS_KEPT_DAYS}} days.{{/IF}}{{#IF LOGS_NOT_KEPT}} Console logs are not sent to any storage; nothing persists beyond the live console stream.{{/IF}}
  • Microsoft Entra ID records sign-ins in your own tenant, as for any app.

/check runs in the browser

The page /check runs the same engine in the visitor’s browser (Python compiled to WebAssembly). Files dropped there are read in the browser and are not uploaded; the page’s content security policy does not let it send requests with them. It sends only two anonymous events to {{DOMAIN}}, that the engine has loaded and that a check is done, with no file contents, file names or table names. No account and no Entra app are involved.

Network: hosts to allow

The Krusgraph Model item in Microsoft Fabric (the Krusgraph workload) loads its editor from our own host inside Fabric’s page. A web filter or proxy that blocks new domains stops it before anything is read. Allow these two hosts:

HostPort and protocolWhat it is for
workload.krusgraph.com443, HTTPS, TLS 1.2 or laterThe Krusgraph Model editor that Fabric shows in its frame, and the engine it calls (/workload/v1), which reads and builds as the signed-in person.
krusgraph.com443, HTTPS, TLS 1.2 or laterThe documentation, help, privacy and terms pages the workload links to, and the MCP connector for AI clients.

Symptom: Krusgraph Model keeps loading in Fabric, or the browser shows ERR_SSL_VERSION_OR_CIPHER_MISMATCH for workload.krusgraph.com. Both hosts support TLS 1.2 and 1.3; this error comes from a filter that intercepts a domain it does not know yet, not from the server. Ask your IT department to allow the two hosts above, then reload the Fabric tab.

Fabric itself (app.fabric.microsoft.com) and Microsoft sign-in (login.microsoftonline.com) must be reachable as for any Fabric use.
